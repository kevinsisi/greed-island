# Honest read-model availability

The sole cookie game client SHALL distinguish an existing own wallet from an uninitialized wallet and an unavailable read. It SHALL preserve actual balances and SHALL NOT create a wallet or invent zero/default balances from absence. Existing purchase controls SHALL require a confirmed sufficient balance.

Private wallet responses SHALL be bound to the owning numeric account and captured session epoch. Concurrent reads SHALL coalesce; inconclusive reads SHALL become unavailable within a bounded interval. Obsolete read results SHALL NOT restore state after session replacement or view disposal.

Owned-card energy/perception SHALL preserve explicit null readiness. A missing perceived timer SHALL NOT be replaced by private raw timing data or an invented local deadline. Public read models SHALL tolerate intentionally omitted private fields and retain reviewed public image/crew/evidence data only when supplied by their canonical producer.
